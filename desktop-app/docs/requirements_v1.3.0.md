# ウマ娘常駐管理型因子管理ツール 要件定義書 (v1.3.0)

## 1. プロジェクト概要
Steam版「ウマ娘 プリティーダービー」を対象とし、育成完了時の因子情報を自動キャプチャ・データ抽出・アップロードし、Web上で検索できるエコシステムを構築する。利用規約を厳守する完全パッシブなクリーンツールとする。

## 2. 前提環境・制約事項 (非機能要件)
- **対象OS:** Windows 10 / 11 (64bit) のみ（`windows-sys`のWin32 APIを使用するため）。
- **対象解像度・画面モード:** Steam版のウィンドウモードまたは仮想フルスクリーンモードで、解像度 1920×1080 (FHD) 以上を動作要件とする。
- **対象ウィンドウ名 (Steam版対応) [重要]:** Steam版の内部ウィンドウタイトルである `UmamusumePrettyDerby_Jpn` をメインターゲットとする（従来DMM版の日本語タイトル「ウマ娘 プリティーダービー」にも両対応する）。
- **DPIアウェアネス [重要]:** Windowsのディスプレイスケーリング（125%や150%など）による論理ピクセルと物理ピクセルの座標ズレを防ぐため、システムは「DPIアウェア」として動作させる。
- **画面レイアウト前提:** Steam版特有の16:9スプリットUIレイアウト（左側にメイン画面、右側にログ等が表示される仕様）を前提とする。
- **環境構築ゼロ:** ユーザー側での事前環境構築を一切不要にするため、OCRエンジン本体と学習データ（日本語の`tessdata`等）はアプリ内に完全同梱・ポータブル化する（Tesseract.jsなどのWebAssembly技術を活用し、C++環境への依存を排除）。

## 3. コア機能とワークフロー
1. **ウィンドウ検知とキャプチャトリガー (手動開始＋自動終了)**
   - [検知条件の厳格化] ウィンドウ検索は、タイトル名とクラス名（`UnityWndClass`）の複合条件で行い、内部のヌル文字等を除去した上で正確にゲーム画面のみを捕捉する。
   - Rustバックエンドによる高精度な一定間隔（200ms）キャプチャ。
   - [自動終了] システムが画面のスクロール最下部への到達（一定回数フレーム間のピクセル差分が閾値以下）を検知し、自動でキャプチャを終了する。
2. **画像結合とクロップ (Rust & OpenCV.js 連携)**
   - **[変更点]** 取得したフレーム群をRust側でローカルキャッシュとして一時保存し、フロントエンド（OpenCV.js）にパスを渡す。
   - フロントエンド（OpenCV.js）の強力なテンプレートマッチング機能（`TM_CCOEFF_NORMED`）を用いて、高速かつ高精度に縦長の因子レシート画像を合成する。
   - スクロールバー領域の排除や、動的要素（ヘッダー・フッター）の自動検出と切り抜きもOpenCV.js側で行う。
3. **ローカルプールとOCR・画像解析 (フロントエンド / WebAssembly)**
   - **[変更点]** 結合された画像に対して、フロントエンド上で Tesseract.js を用いて文字抽出を行う。
   - テンプレートマッチングを利用した親ウマ娘のアイコン自動推測。
   - [精度向上] Tesseractの読み取り精度を最大化するため、ウマ娘のスキル名や特性に合わせたカスタム辞書（ホワイトリスト/ユーザーパターン）や、画像二値化の前処理（OpenCV.js利用）を行う。
   - ユーザーが手動で最終確認・修正できるUIの提供。
4. **Webアップロードと検索 (BaaS連携)**
   - テキストデータのみをSupabaseへアップロード。
   - [Web機能] 3種基本因子（青・赤・緑）および白因子のAND検索、星数フィルター。

## 4. エラーハンドリングと例外処理
システムで発生したエラーは、WindowsのOS通知には極力頼らず、スマートなUI通知を行う。
1. **対象未起動エラー**: ウマ娘アプリが起動していない状態で実行された場合、画面上に分かりやすいエラーメッセージを表示する。
2. **完全な解析失敗時の自動破棄**: キャプチャ画像から文字が全く抽出できなかった場合、データは保存せず自動破棄し再試行を促す。
3. **部分的な解析エラー（新スキル等）**: 一部でもデータが抽出できた場合はローカルDBに保存するが、「要修正」フラグを立て、確認UIにて赤字ハイライトで手動修正を促す。
4. **通信エラー**: Webアップロード失敗時はローカルDBにデータと「未アップロード」状態を保持し、後から一覧画面で再試行可能とする。

## 5. データモデル（DBスキーマ）
1. **profiles テーブル**: id(UUID), trainer_id(String), is_anonymous(Boolean)
2. **factors テーブル**: id, user_id, 代表および親1・親2の[ウマ娘名・青・赤・緑]の種類と星数。
   - ※ローカル保存用（SQLite等）に `is_uploaded` フラグを保持。
3. **white_factors テーブル**: id, factor_id, owner(代表/親1/親2), name(白因子名), stars(星数)。

## 6. UI/UX デザインと画面構成
- **トーン＆マナー**: ガチ勢向けツールとして、目に優しい「ダークテーマ」を基調とし、背景が透ける「グラスモーフィズム（Glassmorphism）」を採用。Tailwind CSSを利用。
- **💻 Tauriアプリ（ローカル）画面**: (1)キャプチャ＆抽出画面 (2)因子詳細＆データ修正画面 (3)設定画面
- **🌐 Webアプリ（クラウド）画面**: (1)因子検索（トップ）画面 (2)検索結果一覧画面

## 7. 技術スタック
- **フロントエンド:** React / Next.js (TypeScript) / Tailwind CSS
- **バックエンド:** Tauri v2 (Rust), windows-sys, image クレート
- **画像処理:** OpenCV.js (WebAssembly)
- **OCR:** Tesseract.js (WebAssembly・ローカル実行・バイナリ内包)
- **DB & 認証:** Supabase (PostgreSQL)
