> 新チャットを開いたら、下記をコピーして先頭に貼る。

## TODO.md 更新（全チャット共通）

`docs/TODO.md` は **進捗の唯一の正本**。Agent mode でコード・設定を変更するチャットでは次を守る。

| タイミング | 必須操作 |
|-----------|---------|
| **着手時**（最初のコード変更と同じコミット） | Backlog → **進行中**（最大1件）、現在のフォーカス・`最終更新:` 更新 |
| **完了時**（完了報告の前） | 進行中 → **完了済み**（コミットハッシュ）、REQ があれば `done` |

- Ask mode の設計レビュー・調査のみ: 進行中は不要（フォーカス更新のみ可）
- Backlog へのメモ追記のみ: 進行中は不要
- 詳細: `docs/TODO.md`「更新ルール」「エージェント必須手順」、`.cursor/rules/docs-management.mdc`

## 2チャット運用（設計 → 実装）

大きめの変更（Tauri 改修・保存方式変更など）は、次の順で進める。

| 順番 | 種別 | モード | 目的 |
|------|------|--------|------|
| 1 | 設計レビュー | **Ask mode** | 方針合意（コード変更なし） |
| 2 | 実装 | Agent mode | 承認済み完成プロンプトに従って実装 |

**調査チャットとの違い**

- **調査** — 原因究明（バグ・データ不整合など）
- **設計レビュー** — これから作る機能の方針合意（比較・推奨案・実装用完成プロンプト）

**出力の2パターン（通常は A を使う）**

| パターン | 用途 | 設計レビューが出すもの |
|---------|------|----------------------|
| **A. 完成プロンプト一発**（推奨） | 承認後すぐ実装 | 下記「承認後・実装チャット用」テンプレートを**すべて埋めた1ブロック** |
| **B. 中身のみ** | 方針だけ先に確認したい | 「承認済み方針」欄の本文のみ。外枠は手動でテンプレートに貼る |

承認時の返信例（設計チャット側・**パターン A 推奨**）:

```
承認します。

実装チャット用の完成プロンプトを出力してください。
要件:
- 本ファイル「承認後・実装チャット用（Agent mode）」の外枠をそのまま使う
- 「承認済み方針」欄に、本チャットの設計レビュー結果（未決事項の回答含む）を全文入れる
- @docs 参照・チャット種別・進め方・背景・触る/触らない・完了条件まで含め、Agent mode 新チャットにそのまま1回で貼れる1ブロックにする
- コピー範囲が分かるよう「▼ここからコピー」「▲ここまで」を付ける
- 表やネストしたコードブロックは使わず、プレーンテキストのコードブロック1つにまとめる

（実装は次の新チャットで行います）
```

未決事項への回答と同時に承認する場合:

```
（案・未決事項への回答）

上記を反映したうえで、CHAT_TEMPLATE.md「承認後・実装チャット用」を
外枠ごと埋めた完成プロンプトを1ブロックで出力してください。
```

## 設計レビューチャット用（Ask mode）

> **必ず Ask mode** で起票する（Agent mode だと承認後に同チャットで実装が始まりやすい）。
> 個別要件がある場合は `@docs/tasks/REQ-*.md` を追加する。

```
@docs/PROJECT.md
@docs/TODO.md
@docs/tasks/REQ-（タスク名）.md

## チャット種別
設計レビュー（Ask mode）

## 進め方（重要）
- このチャットでは **コード変更・ファイル編集・コミットを一切しない**
- 現状整理 → 方針提案 → 変更範囲 → リスク → 検証手順 まで提示する
- 私が「承認」「修正」「見送り」のいずれかを返すまで、実装に進まない

## 背景
（docs/TODO.md のどの項目か。例: P1 Gemini API キーのセキュアストレージ化）

## 今回決めたいこと
（1タスクに絞る。例: 保存先を Tauri セキュアストレージへ移行する方針）

## 確認してほしいファイル
- （例）desktop-app/app/(main)/page.tsx
- （例）desktop-app/src-tauri/

## 触らないこと（設計上も変更提案に含めない）
- （例）app/lib/geminiOcr.ts — OCR ロジック本体
- （例）app/lib/fuzzyMatcher.ts

## 報告形式（この順で）
1. **現状整理** — 関連ファイルとデータの流れ
2. **選択肢比較** — 2〜3案（メリット / デメリット / 適合度）
3. **推奨案（1つ）** — 採用理由
4. **変更計画** — 触るファイル / 触らないファイル / 責務分担
5. **移行・互換** — 既存データの扱い（あれば）
6. **UI・UX 変更** — ユーザー向け文言の変更（あれば）
7. **リスク・未決事項** — 判断が必要な点を質問形式で
8. **検証手順** — 実機確認チェックリスト
9. **実装チャット用完成プロンプト** — 下記「承認後・実装チャット用（Agent mode）」の外枠を埋めた全文（パターン A）
   - `@docs` 参照・チャット種別・進め方・承認済み方針・背景・触る/触らない・完了条件を含む
   - 承認済み方針には本レビューの合意内容（推奨案・未決事項の回答・移行手順等）を詳述
   - Agent mode 新チャットに **1回で貼れる1ブロック**（`▼ここからコピー` / `▲ここまで` マーカー付き）
   - 表やネストしたコードブロックは使わない（コピーしやすいプレーンテキスト1つ）

## スコープ（REQ があれば要約）
### やること
- 

### やらないこと
-
```

- **パターン B**: 下記テンプレートを手動で埋め、「承認済み方針」に設計レビューの方針本文のみ貼る

**テンプレート骨格**（設計レビュー §9 がこの形式で出力する。実装時は完成形を貼る）:

```
-
```

## バグ報告チャット用

> 検証中・実装後に見つけた不具合向け。
> **日常は短縮版**、キャプチャ/OCR/Rust など **コア領域・重大バグは詳細版**。

### 依頼の一言（これだけ差し替えればよい）

| やりたいこと | 依頼の一文 |
|-------------|-----------|
| **調査→承認→修正**（**日常の推奨**） | 原因調査と修正案を先に提示。問題なければそのまま実装して。 |
| 調査のみ | 原因と修正案だけ。修正・コミットはしない。 |
| 即修正 | 原因調査のうえ最小修正まで OK。 |

---

### 短縮版（日常・軽微向け・推奨）

```
@docs/tasks/REQ-（関連があれば）.md

Agent mode。

（検証○ / 実装後）で再現。
期待: 
実際: 
手順: 

原因調査と修正案を先に提示。問題なければそのまま実装して。
触るのは （例: src-tauri/Cargo.toml 周り） まで。
```

**記入例（keyring ケース）:**

```
@docs/tasks/REQ-secure-api-key.md

Agent mode。

検証1で再現。
期待: キー保存 → 完全終了 → 再起動 → 設定済み・OCR 成功
実際: 再起動後に未設定に戻る
手順: キー保存 → トレイから完全終了 → tauri dev で再起動

原因調査と修正案を先に提示。問題なければそのまま実装して。
触るのは src-tauri/Cargo.toml / api_key 周りまで。
```

**承認の返信（1行）:** `承認。推奨案で。`

### 詳細版（重大バグ・コア領域向け）

範囲が広い・影響が大きい・触ってはいけない領域に及ぶときだけ使う。

#### 使い分け

| パターン | モード | 向いているケース |
|---------|--------|-----------------|
| A. 調査のみ | Ask | 原因把握・方針選択。修正は別チャット |
| B. 調査→承認→修正 | Agent | 短縮版と同趣旨だが触る/触らない・完了条件を明文化 |
| C. 調査+修正まで | Agent | 短縮版の「即修正」に加え、完了条件を明文化 |

#### A. 調査のみ（Ask mode）

```
@docs/PROJECT.md
@docs/tasks/REQ-（関連）.md

Ask mode。コード変更・コミット禁止。

期待 / 実際 / 再現手順:
触らない: （例）src-tauri/src/capture.rs

報告: 原因・根拠・修正案（2案以内）・推奨案・検証手順
```

#### B. 調査→承認→修正（Agent mode）

```
@docs/PROJECT.md
@docs/tasks/REQ-（関連）.md

Agent mode。原因・修正案提示後、承認まで実装しない。

期待 / 実際 / 再現手順:
触ってよい（承認後）: 
触らない: 

承認後: 推奨案どおり最小修正。コミット可（push 不可）
```

#### C. 調査+修正まで（Agent mode）

```
@docs/PROJECT.md
@docs/tasks/REQ-（関連）.md

Agent mode。原因調査 → 最小修正まで。想定外に広がったら止めて報告。

期待 / 実際 / 再現手順:
触ってよい: 
触らない: 
完了: 再現手順で解消・コミット（push 不可）
```
