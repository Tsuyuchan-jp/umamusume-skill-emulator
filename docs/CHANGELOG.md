## v1.3.0 — 2026-07-23

### 新機能

- **長距離レース連続シミュレーションの失敗走スキップ** — 本家 umasim の `RaceOperation`（レース実行処理）と同様、内部エラーで落ちた走だけスキップし、成功した走で集計を続行。1走の例外でバッチ全体が ERROR にならない（成功が1走以上あれば結果を返す）
- **完走数表示** — 結果タブヘッダー右（ステータス条件ボタンの左）に `n/N走` を表示。カーソルを合わせると `シミュ完走〇走 失敗〇走` のツールチップを表示。失敗0は控えめ、失敗ありは琥珀色で強調

### 修正

- **長距離レース（中山3600m）連続シミュレーション失敗** — v1.2.0 既知の問題を解消（逃げ/先行/差し×低スタミナでも成功分の結果を表示）
- **シミュレーション完了トースト** — 失敗走があるとき「N回中M回完走しました（K回は内部エラーのためスキップ）」と表示。比較検証も同方針
- **全滅時の挙動** — 成功0のときは ERROR トーストのみ（結果タブを作らない）。日本語理由は Step1 維持
- **スパート率・各種 rate の分母** — 指定回数ではなく成功回数（`completedCount`）を分母に統一
- **レース条件ラベル** — `RaceInfoLabel`（レース情報ラベル）から試行回数の「〇走」を削除（完走数はヘッダーに集約）
- **スパート率チップのレイアウト** — タイム表示枠と同じ高さに揃え、スパート率表示との混同を防止

### データ

- スキルマスタ **2042件**（v1.2.0 から変更なし）

### ビルド

- 配布正本: `desktop-app/src-tauri/target/release/app.exe` 更新（`npm run build:release-exe`）

- **エラートースト** — `type: error` の長文を折り返し・複数行で全文表示（success は従来どおり1行 truncate）
- **シミュレーションエラー表示** — Worker の null 文字列 / 空メッセージを超長距離向け日本語案内へ変換（`SIMULATION_NULL_ERROR_MESSAGE`）

## 運用（Unreleased の維持）

**読者**: 主に **人間**（共同開発者・配布前の確認者）。「前回リリース以降、ユーザーに何が変わるか」を一覧で見るための欄。

### 役割分担

| ドキュメント | 役割 |
|-------------|------|
| [`TODO.md`](TODO.md) | 開発進捗の正本（着手・完了・実機クローズ） |
| [`tasks/REQ-*.md`](tasks/REQ-*.md) | 設計・スコープ・決定ログ |
| **CHANGELOG `Unreleased`** | **次回リリースに載せる変更の下書き**（人間がチェックしやすい束ね） |
| **CHANGELOG `vX.Y.Z`** | 確定したリリース履歴（配布・振り返り用） |

`Unreleased` は TODO の代替 **ではない**。エージェントの作業ログも **書かない**。

### いつ `Unreleased` に追記するか

次の **すべて** を満たすとき、**完了コミットと同一コミット内** で追記する（推奨・漏れ防止）。

1. **ユーザーに見える変化**がある（UI・挙動・データ・配布物）
2. 実装が **完了** している（`TODO` 完了済み、または実機検証クローズ済み）
3. 次回バージョンに **含める意図**がある（リリース予定の変更）

例: OCR モデル変更、新ボタン、sim 挙動修正、スキルマスタ件数更新。

### いつ追記しないか

- **着手時のみ**（進行中のメモは `TODO`）
- 挙動・UI が変わらない **内部整理のみ**（リファクタ、テスト追加、コメント）
- **`docs/`・`.cursor/rules` のみ**の運用整備（本ファイルの運用節追記など）
- **まだ実機未検証**の WIP（検証クローズ後に追記）
- バージョン bump **だけ**の作業（そのときは下記「リリース時」手順で節を昇格）

迷ったら **追記しない** より **1行で書く** 方を選ぶ（リリース前に人間が削れる）。

### 書き方（1行の型）

カテゴリ見出しの下に、次の形式で **1変更 = 1行**。

    - **（ユーザー向けの短いタイトル）** — （何がどう変わるか。1文）

**カテゴリ**（必要なものだけ使う。空カテゴリは書かない）:

| 見出し | 使うとき |
|--------|----------|
| `### 新機能` | 新しい画面・操作・能力 |
| `### 修正` | バグ・誤動作の解消 |
| `### 改善` | 既存機能の品質・UX 向上（バグではない） |
| `### データ` | スキルマスタ件数・同梱データの更新 |
| `### ビルド` | 配布 `app.exe` の更新（リリース作業時に追記） |
| `### ドキュメント` | 利用者向け README 等の大きな変更 |
| `### 既知の問題` | 未解決だが次回以降で対応予定の事象（任意） |

- 太字タイトルは **機能名・画面名** ベース（関数名・ファイル名は避ける）
- 技術詳細は REQ / git に任せ、ここは **配布前の人間チェック** 用に平易に

### リリース時（`Unreleased` → `vX.Y.Z`）

[`RELEASE_BUILD.md`](RELEASE_BUILD.md) のバージョン bump と **同じ作業列** で行う。

1. `desktop-app/package.json` の `version` を更新（正本）
2. **`Unreleased` の全項目** を新しい `## vX.Y.Z — YYYY-MM-DD` 節へ **移動**（コピーではなく昇格）
3. 必要なら `### ビルド`・`### データ` を追記（`app.exe` 更新済み・件数など）
4. **`Unreleased` を空に戻す** — 見出しだけ残し、中身は `（なし）` と1行
5. `npm test` → `npm run build:release-exe`（手順は RELEASE_BUILD 正本）

リリースコミットに **Unreleased の昇格と version bump を含める**（別日に分けない）。

### 人間の定期チェック（配布前）

- [ ] `Unreleased` の各行が、実際に触って確認したい変更と一致しているか
- [ ] `TODO` 完了済みのうち **ユーザー向け** のもので、漏れていないか
- [ ] 載せたくない行（内部のみ・取り消し）がないか
- [ ] リリース後、`Unreleased` が `（なし）` に戻っているか

### エージェント（Cursor）

| タイミング | 動作 |
|-----------|------|
| ユーザー向け変更の **完了コミット前** | 上記「いつ追記するか」を満たせば `Unreleased` に1行追加 |
| **リリース / version bump** | `Unreleased` を新バージョン節へ昇格し、空に戻す（必須） |
| **TODO 着手時** | `Unreleased` は触らない |

詳細の入口: [`DOCS-GUIDE.md`](DOCS-GUIDE.md)「永続正本同期表」— バージョン bump・リリース行。
