## 解くべき問題と目的（Problem Framing）

- **現状の課題**: シミュ用 `skill_data.txt` はオンライン取得できるが、OCR／パレットは同梱 `umasimSkillData.ts` のため、新スキルのたびに再配布が必要だった。プリセットも同梱 JSON の手動更新だった。
- **目的**: 起動時に umasim からシミュ JSON を取り、一覧をその場で作り、成功／失敗をトーストする。開催ローテも同じ作者追従でボタン化する。

---

## スコープ

### やること

- 起動時: シミュ JSON 取得 → 一覧 JSON 生成 → トースト A〜D
- 設定「スキルデータ（診断）」: いまの取得元とプリセット件数。ボタン「最新のスキルデータを取得する」
- `event_track.txt` フェッチ。旧 `race_presets.json` 削除
- LoH（5 列目なし）はバ場デフォルト（良）。取得失敗時はプリセット非表示

### やらないこと

- データハブ一元化
- `race.js` / WASM の実行時更新
- `trackData.ts` のフェッチ化
- 案B（自前 GitHub への skill_data 置き場変更）

## 仕様

### トースト（起動時・手動更新で共通）

| 記号 | 条件 | 文言 | 種別 |
|------|------|------|------|
| A | umasim 取得成功 | スキルデータを最新版（umasim）に更新しました | success（毎回出す） |
| B | 保存済みで続行 | オンライン取得に失敗したため、保存済み／同梱のスキルデータで続行しました（最新版ではない可能性があります）。 | error |
| C | 同梱で続行 | オンライン取得に失敗したため、アプリ同梱のスキルデータで続行しました（最新版ではない可能性があります）。 | error |
| D | 全滅 | スキルデータの取得に失敗しました。インターネット接続をご確認のうえ、もう一度お試しください。 | error |

シミュ完了時のフォールバックトーストは、起動／手動ですでに出していれば出さない。

### 診断枠

- スキル: 最新（OCR・パレット・sim 同一）／保存済み／同梱／未取得／確認中
- プリセット: N 件取得／取得できず非表示
- ボタン: 最新のスキルデータを取得する（取得中は「取得中…」）

### プリセット

- 正本: umasim `data/event_track.txt`
- チャンミ: 9 人・5 列目のバ場
- LoH: 12 人・バ場は良（ユーザーが手動変更）

## 設計制約（契約）

- **事前条件**: オンライン時は `raw.githubusercontent.com`（mee1080/umasim）へ到達できる
- **事後条件**: 取得成功時、OCR／パレット／sim が同じシミュ JSON 由来になる
- **不変条件**: 同梱 `umasimSkillData.ts` / `public/skill_data.txt` はオフライン予備として残す
- **異常時の保証**: スキル全滅は D。プリセット失敗は空（ボタンなし）。既存のキャプチャ／OCR フローは変えない
