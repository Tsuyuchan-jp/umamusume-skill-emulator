# REQ-auto-capture-multi-screen: オートキャプチャの複数ゲーム画面対応

> 殿堂入り経路以外のステータス確認画面でも、自動スクロールキャプチャが安定動作するようにする。

## 目的

現状、オートキャプチャ（`start_auto_scroll_capture_session`）は **殿堂入りウマ娘一覧** から開いた **ステータスページ・因子ページ** のレイアウトに最適化されており、他の経路ではヘッダー検知・スクロール領域・終了条件が合わず失敗しやすい。

育成フローやフレンド閲覧など、ステータスを確認する代表的な画面でも **同じショートカット／ボタン操作でキャプチャ→結合→OCR** まで通せるようにする。

---

## 背景（現状整理）

| 項目 | 内容 |
|------|------|
| エントリポイント | `CapturePanel` → `useCapture` → Rust `start_auto_scroll_capture_session` |
| 画面検知 | `find_factor_header_bounds` — 緑色ヘッダーバーの X/Y 範囲を画像から推定 |
| スクロール | ヘッダー Y 〜 クライアント高さ 90% の中央へホイール送信 |
| 終了条件 | ① `detect_green_history_bar`（継承履歴バー＝因子ページ想定）② フレーム差分が小さい＝スクロール末端 |
| 既知の動作する経路 | **殿堂入りウマ娘一覧** → ウマ娘 **ステータス** / **因子** ページ |

### 追加対応したい画面（ユーザー要望）

| # | 画面（ゲーム内） | 備考 |
|---|----------------|------|
| A | **育成完了時の確認ページ** | 育成終了後の総合ステータス確認 |
| B | **育成完了直前のスキル取得前後の確認ページ** | 最終スキル取得前後のステータス確認（スクロール量・終了位置が A と異なる可能性） |
| C | **フレンドのウマ娘を確認時** | フレンド詳細からのステータス閲覧（UI 枠・ヘッダー位置が殿堂入りと異なる可能性） |

> 実装前に各画面の **スクリーンショット** と「キャプチャすべき縦範囲（ステータス〜スキル一覧末尾）」を設計レビューで確定する。

## スコープ

### やること

- [`capture.rs`](../../desktop-app/src-tauri/src/capture.rs) のオートスクロールロジックを、**複数画面プロファイル**で動作するよう拡張
  - ヘッダー／スクロール領域の推定
  - 終了条件（継承履歴バー検知の要否、差分閾値、最大フレーム数等）
- 既存の **殿堂入り → ステータス／因子** 経路の挙動を **退行させない**
- 実機検証手順の明文化（各経路で結合画像が OCR 可能な縦範囲をカバーすること）
- 必要なら `CapturePanel` に「対応画面の目安」を短文追記（任意）

### やらないこと

- 手動スクロールキャプチャの UI 変更（既存フロー維持）
- OCR（`geminiOcr.ts`）・`fuzzyMatcher.ts` の変更
- ゲーム解像度・ウィンドウモード以外の Win32 ウィンドウ検出ロジックの全面刷新
- 因子ページ以外の **非ステータス系画面**（レース結果・ショップ等）への汎用対応
- キャプチャ以外の育成フロー連携（自動画面遷移等）

## 仕様（設計レビューで詰める項目）

### 画面プロファイル（案）

```
enum CaptureScreenProfile {
  HallOfFame,           // 現行（殿堂入り経路）— デフォルト・回帰正本
  TrainingComplete,     // 育成完了確認
  TrainingSkillConfirm, // 育成完了直前スキル取得前後
  FriendUma,            // フレンドウマ娘確認
}
```

- 初回フレームから **自動判定**（ヘッダー色・位置・固有 UI 要素）。判定不能時は現行 `HallOfFame` 相当でフォールバック＋ログ
- プロファイルごとに切り替えるパラメータ例:
  - `find_*_header_bounds` の探索 Y 範囲
  - スクロールアンカー（client Y）
  - `detect_green_history_bar` の有効/無効
  - 差分ベース終了の閾値・連続同一フレーム回数
  - 安全のための **最大スクロール回数** 上限

### 完了の定義（各経路共通）

- オートキャプチャ完了後、結合画像に **ステータス（5 能力＋適性）とスキル一覧の末尾** が含まれる
- 殿堂入り経路で従来通り動作（回帰）
- 失敗時は既存と同様に Rust 側で日本語エラーを返す

## 検証手順（案）

各経路で **ゲームを該当画面まで手動で遷移** → アプリでオートキャプチャ（ショートカット or ボタン）→ 結合プレビュー確認 → OCR 実行。

| # | 経路 | 確認 |
|---|------|------|
| 0 | 殿堂入り一覧 → ステータス／因子 | 回帰（現行どおり） |
| 1 | 育成完了確認ページ | 結合画像・OCR 成功 |
| 2 | 育成完了直前スキル取得前後 | 同上 |
| 3 | フレンドウマ娘確認 | 同上 |

## リスク・注意

| リスク | 対策 |
|--------|------|
| ゲーム UI 更新で色・レイアウトが変わる | プロファイル分離・閾値を定数化・ログで判定結果を出す |
| 誤判定でスクロールしすぎ／足りない | 最大スクロール回数・手動停止（既存）を維持 |
| `capture.rs` は実機検証済み領域 | 差分をプロファイル追加に閉じ、殿堂入り経路は最後に必ず回帰 |
| 解像度・ウィンドウモード差 | 設計レビューで Steam/DMM・推奨解像度を明記 |
