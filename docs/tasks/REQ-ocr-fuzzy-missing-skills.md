## 解くべき問題と目的（Problem Framing）

- **現状の課題**: 実機 OCR 後、所持スキル一覧に「千鍛万錬」「快速」「逃げためらい」が載らないことがある（ユーザー報告）
- **目的**: 原因を層ごとに特定し、3スキルが OCR → 一覧（必要なら sim）に載るようにする。原因が OCR 欠落 / マッチ失敗 / DB 欠落のどれか混在しうる

## 調査結果（2026-08-10）

### パイプライン（用語）

```
結合画像 → Gemini OCR（生の skills 文字列配列）
         → fuzzyMatchSkillId（umasimSkillNames と類似度比較）
         → sanitizeSkillIds → SkillPanel 一覧
```

- **ファジーマッチ**（`fuzzyMatchSkillId`）: OCR 文字列とローカルスキル名一覧の類似度を取り、閾値 **0.45 未満**は空文字（＝一覧から除外）
- **正本データ**: マッチは `umasimSkillData.ts`（＝ umasim `skill_data.txt` 由来）。`skillRarityData`（mdb）は表示色用で、ID 解決には使わない

### スキル別

| スキル | mdb（`text_data` cat=47） | umasim / `umasimSkillData` | 完全一致のマッチ | 結論（現時点） |
|--------|---------------------------|----------------------------|------------------|----------------|
| 千鍛万錬 | ID `204031` | あり（rare） | rating 1.0 → 通る | DB 欠落ではない。OCR 欠落 **または** 誤読で閾値未満の可能性 |
| 快速 | ID `202552` | あり（normal） | rating 1.0 → 通る | 同上。2文字名のため誤読・欠落に弱い |
| 逃げためらい | ID `200851` | **無し**（上流 umasim `skill_data.txt` にも無し） | 最良 0.29（大逃げ）→ **除外** | **DB 欠落が確定**。OCR が正しくても一覧に出ない |

### ファジー感度（机上プローブ）

`string-similarity` + 閾値 0.45・アプリ同等の空白正規化で計測。

| OCR 想定入力 | 最良一致 | rating | 0.45 通過 |
|--------------|----------|---------|-----------|
| 千鍛万錬 | 千鍛万錬 | 1.00 | ○ |
| 千鍛万練 / 連 | 千鍛万錬 | 0.67 | ○ |
| 千段万錬（鍛→段） | 千鍛万錬 | **0.33** | **×** |
| 千銀万錬（鍛→銀） | 千鍛万錬 | **0.33** | **×** |
| 快速 | 快速 | 1.00 | ○ |
| 快足 / 快遠 | （不一致） | 0 | × |
| 逃げためらい | 大逃げ | 0.29 | × |

**示唆**: 「千鍛万錬」は **鍛→段** のような1文字誤読でも落ちる。完全一致なら落ちない → 実機で落ちているなら、生 OCR に正しい名前が無い／誤読されている可能性が高い。

### 逃げためらい周辺（umasim 未収録の範囲）

mdb 上の同系統（いずれも umasim `skill_data.txt` に ID 無し）:

| ID | 名前 |
|----|------|
| 200831 / 200841 / 200851 | 逃げけん制 / 逃げ焦り / **逃げためらい** |
| 200861 / 200871 / 200881 | 先行けん制 / 先行焦り / 先行ためらい |
| 200891 / 200901 / 200911 | 差しけん制 / 差し焦り / 差しためらい |
| 200921 / 200931 / 200941 | 追込けん制 / 追込焦り / 追込ためらい |

※ 妨害スキル（他ウマ娘へのデバフ）。umasim 側は「他者効果は無視」の固有はあるが、この白スキル群の定義行自体が無い。

### 未確定（実装前に要実機）

- 現状 **Gemini の生 `skills` 配列を保存・表示する経路が無い**（`normalizeStatusData` 直後にマッチ結果だけ残る）
- 「千鍛万錬」「快速」について、OCR 欠落とマッチ失敗の切り分けは **生 JSON 確認が必要**

## 設計制約（契約）

- **事前条件**: OCR 用 API キーあり。マッチ正本は `umasimSkillData`（現状維持）
- **事後条件**: 合意した方針どおり、対象スキルが SkillPanel に表示される（sim 可否は方針に従う）
- **不変条件**: 既存スキルの誤マッチ率を意図せず悪化させない。sim 未定義スキルを黙って WASM に渡して落とさない
- **異常時の保証**: マッチ失敗は従来どおり除外（空文字）。診断ログは本番 UX を壊さない
