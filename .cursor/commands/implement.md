## チャット種別
実装（Agent mode・設計レビューなしの小規模タスク）

## 対象範囲の自己点検（最初に行う）
このコマンドに続けてユーザーが書いた内容を「今回やること」として扱う前に、まず次を確認する：
- スコープが1タスクに絞れているか
- 判断が必要な選択肢（設計上の分岐）が残っていないか
- `docs/PROJECT.md` の「触ってはいけない領域」に踏み込む可能性がないか

いずれかに該当する、または範囲が広いと感じたら、実装を始めずに **「設計レビューが必要な規模に見えます。`/design-review` の利用を推奨します」** と報告して差し戻す。

## 今回やること
（上記の自己点検を通過した場合のみ）ユーザーの指示と `docs/TODO.md` の該当項目から、今回やることと触るファイル/触らないファイルを整理してから着手する。

## 完了条件（必須・毎回）
- [ ] 実機確認できる条件を満たしている
- [ ] **着手時**: `docs/TODO.md` の対象を Backlog → 進行中（最大1件。既存の進行中があれば先に完了/保留にしてから移す）へ移し、「現在のフォーカス」・`最終更新:` を更新する。日時は必ずシェルで `Get-Date -Format "yyyy-MM-dd HH:mm"` を取得する。最初のコミットに含める
- [ ] **完了時**: 進行中 → 完了済み（コミットハッシュを添える）、`最終更新:` 更新
- [ ] **永続正本同期**: `docs/DOCS-GUIDE.md`「永続正本同期表」に該当トリガーがあれば従う
- [ ] ユーザー向けの変更なら `docs/CHANGELOG.md` の `Unreleased` に1行追記
- [ ] コミット作成（push はしない）

## 検証
`docs/CHAT_TEMPLATE.md`「検証コマンド（共通）」の該当節を実行し、結果を報告する。

## 完了報告時
実装完了後、実機検証を依頼する1行を添える（例:「確認できたら新しいチャットで `/verify-close` をお願いします」）。
