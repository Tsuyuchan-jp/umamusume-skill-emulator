Agent mode。

このコマンドに続けてユーザーが書いた内容を、次の形式で解釈する（不足があれば質問で止めず、妥当な仮定を置いたうえで先頭に「仮定: 〜」と明記して進める）：
- 再現状況（検証中 / 実装後）
- 期待
- 実際
- 再現手順

## 進め方
まず原因調査と修正案を提示する。問題なさそうならそのまま実装してよい。
ただし次のいずれかに該当する場合は、実装せず一旦止めて報告する：
- OCR（`geminiOcr.ts`）・ファジーマッチ（`fuzzyMatcher.ts`）・キャプチャ / Rust（`src-tauri/`）などコア領域に触れる
- 影響範囲がユーザーの申告より明らかに広い
- 修正方針が2案以上に割れ、どちらとも決めがたい

このときは「コア領域・影響範囲が大きいため、`/investigate`（詳細調査）または `/design-review` を推奨します」と報告する。

関連する `docs/tasks/REQ-*.md` があれば読む。無ければ本文に「触ってよい範囲」を明記して進める。

## 完了条件（実装した場合・必須）
- [ ] **着手時**: `docs/TODO.md` の進行中へ移す（既存の進行中があれば先に完了/保留に）。`最終更新:` は `Get-Date -Format "yyyy-MM-dd HH:mm"` で取得
- [ ] **完了時**: 完了済みへ追記（コミットハッシュ）。関連 REQ があれば決定事項ログに1行
- [ ] 永続正本同期（`docs/DOCS-GUIDE.md`「永続正本同期表」）
- [ ] コミット作成（push はしない）

## 完了報告時
実装完了後、実機検証を依頼する1行を添える（例:「確認できたら新しいチャットで `/verify-close` をお願いします」）。
