# .cursor/commands 導入手順

## 導入方法
1. リポジトリ直下に `.cursor/commands/` フォルダを作成する
2. このフォルダ内の6つの `.md` ファイル（README.md 以外）をそのままコピーする
3. Cursor の Agent 入力欄で `/` を押すとコマンド一覧に表示される

## 使用例
- 設計レビュー: 新チャットを開き `/design-review 賢さ判定による不発動スキル表示を検討したい` のように入力
- 承認後の実装: 別の新チャットで `/implement-approved` を実行し、続けて design-review が出力した引き継ぎブロックを貼り付ける
- 設計レビュー不要な小規模実装: `/implement TODO の P2「StatusPanelのスキル表示に色分け」を対応`
- 調査: `/investigate OCR後に千鍛万錬が一覧に出ない原因を調べて`
- バグ報告（日常向け）: `/bug-report 検証1で再現。期待:～ 実際:～ 手順:～`
- 実機検証クローズ: `/verify-close 対象:継承進化special対応 / コミット:7bbaeed / 結果:OK`

## 必ず確認してほしいこと（初回導入時）
これは CHAT_TEMPLATE.md の完全な移植ではなく、**動作確認前の第一稿**です。特に以下は元のテンプレートから単純化・省略しています。実際に数回使ってみて、困った点がないか確認してから、CHAT_TEMPLATE.md への手動コピペをやめるかどうか判断することを推奨します。

- **`@` 添付の層（A〜F）・件数の目安**: 今回のコマンドでは `@docs/PROJECT.md` `@docs/TODO.md` の固定添付のみとし、CONCEPT-MAP や REQ・コード正本の追加添付判断はエージェントの自律探索に任せる形に簡略化しています。調査範囲が足りない・広すぎると感じたら、その都度エージェントに直接指示してください
- **モデル推奨ロジック**: 各コマンドの末尾に簡略版を残していますが、CHAT_TEMPLATE.md の詳細な使い分け表（起票依頼チャットとの2種類の推奨の書き分け等）はそのままでは移植していません
- **バグ報告の詳細版**（コア領域・重大バグ向けの調査のみ/調査→承認→修正/調査+修正まで、の3パターン）は含めていません。今回の `bug-report.md` は日常向けの短縮版のみで、コア領域や影響範囲が大きいと判断した場合は実装せず差し戻す設計にしています
- **リリースビルド（バージョン bump）用のコマンド**は今回含めていません。必要であれば別途 `release-build.md` を作成します
- 各コマンドの `docs/PROJECT.md` `docs/TODO.md` へのパス参照は現在のリポジトリ構成に合わせています。今後別プロジェクトで使い回す場合は、同じ `docs/PROJECT.md` `docs/TODO.md` の骨格をそのプロジェクトにも用意してください
