## チャット種別
実装（Agent mode）

## 進め方（重要）
- このコマンドに続けて貼り付けられた「承認済み方針」ブロックに **厳密に従って** 実装する
- 方針と異なる大きな変更が必要になったら **実装を止めて報告**し、再承認を待つ
- ブロックの「REQ」欄が「新規 draft 起票が必要」となっていれば、`docs/tasks/REQ-*.md` を新規作成し、**同一コミットで** `docs/TODO.md` の Backlog にも1行追加する。既存 REQ 名が書かれていればそれを読む

## 完了条件（必須・毎回）
- [ ] 実機確認できる条件を満たしている（ブロック内容および該当 REQ の完了条件に従う）
- [ ] **着手時**: `docs/TODO.md` の対象を Backlog → 進行中（最大1件。既存の進行中があれば先に完了/保留にしてから移す）へ移し、「現在のフォーカス」・`最終更新:` を更新する。日時は必ずシェルで `Get-Date -Format "yyyy-MM-dd HH:mm"` を取得してから書く（推測しない）。最初のコミットに含める
- [ ] **完了時**: 進行中 → 完了済み（コミットハッシュを添える）、REQ があれば `done` に更新・決定事項ログに1行追記、`docs/tasks/INDEX.md` があれば同一コミットで更新
- [ ] **永続正本同期**: `docs/DOCS-GUIDE.md`「永続正本同期表」または該当 REQ の「永続正本同期」節に従い、今回のトリガーに対応する正本を更新したか確認する
- [ ] ユーザー向けの変更なら `docs/CHANGELOG.md` の `Unreleased` に1行追記
- [ ] 新しい用語・概念が出たら `docs/CONCEPT-MAP.md` に追記
- [ ] コミット作成（push はしない）

## 検証
`docs/CHAT_TEMPLATE.md`「検証コマンド（共通）」の該当節（該当する場合は `npm test` / `npm run stitch:golden` 等）を実行し、結果を報告する。

## 完了報告時
実装完了後、実機検証を依頼する1行を添える（例:「tauri dev で〇〇を確認してください。OK なら新しいチャットで `/verify-close` を実行し、この内容を伝えてください」）。
